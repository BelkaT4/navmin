Краткая шпаргалка по 95% операциям, которые встречаются в повседневной работе

---

## 1. Базовые операции

```bash
git init
```
Создать новый репозиторий в текущей папке.


```bash
git status
```
Показать текущее состояние: изменённые, добавленные в индекс, неотслеживаемые файлы.


```bash
git add <файл>
```
Добавить изменения в **индекс (staging area)** — подготовку к коммиту.  
- `<файл>` – имя файла или шаблон (`.` – все файлы в папке).


```bash
git commit -m "сообщение"
```
Создать коммит из проиндексированных изменений.  
- `-m` – флаг для сообщения.


```bash
git log --oneline --graph -5
```
Показать историю коммитов.  
- `--oneline` – сокращённый вывод (каждый коммит в одну строку).  
- `--graph` – визуализация веток.  
- `-5` – последние 5 коммитов.


```bash
git restore <файл>
```
Отменить **незакоммиченные изменения** в рабочем каталоге, вернуть файл к состоянию последнего коммита.


```bash
git restore --staged <файл>
```
Убрать файл из индекса, но **оставить изменения** в рабочем каталоге.  
- `--staged` – убрать из индекса.

## 2. Работа с ветками

```bash
git branch
```
Показать список локальных веток, текущая помечена `*`.


```bash
git branch <имя>
```
Создать новую ветку, но **не переключаться** на неё.


```bash
git checkout -b <имя>
```
Создать ветку и сразу переключиться на неё.  
- `-b` – флаг «создать и переключиться».


```bash
git checkout <имя>
```
Переключиться на существующую ветку.


```bash
git branch -d <имя>
```
Удалить локальную ветку (безопасно, если она уже слита).  
- `-d` – удалить.


```bash
git push origin --delete <имя>
```
Удалить ветку на удалённом репозитории.

## 3. Слияние и разрешение конфликтов

```bash
git merge <ветка>
```
Объединить указанную ветку с текущей. Если в текущей нет изменений — fast-forward. Иначе создаётся merge-коммит.

**Конфликт:**  
В файле появляются маркеры:
```
<<<<<<< HEAD
... ваши изменения ...
=======
... изменения из сливаемой ветки ...
>>>>>>> <ветка>
```
- Оставьте нужный код, удалите маркеры.  
- После правки: `git add <файл>` и `git commit` (можно без `-m`, Git предложит стандартное сообщение).
- Если конфликт был нетривиальный, стоит кратко описать в сообщении, что было сделано


```bash
git status
```
После конфликта покажет файлы с пометкой `both modified`.

## 4. Удалённые репозитории

```bash
git remote add origin <URL>
```
Связать локальный репозиторий с удалённым.  
- `origin` – стандартное имя для удалённого репозитория.  
- `<URL>` – адрес (HTTPS или SSH).


```bash
git remote set-url origin <новый URL>
```
Изменить URL удалённого репозитория (например, с HTTPS на SSH).


```bash
git remote -v
```
Показать все удалённые репозитории и их URL.  
- `-v` – подробный вывод.


```bash
git push -u origin <ветка>
```
Отправить локальную ветку в удалённый репозиторий и установить **upstream** (связь). После этого `git push` и `git pull` будут работать без аргументов.  
- `-u` или `--set-upstream` – установить связь.


```bash
git pull origin <ветка>
```
Загрузить изменения с удалённого репозитория и **слить** их с текущей веткой (`fetch` + `merge`).  

**Рекомендация:** каждый день перед началом работы делайте `git pull origin main`.


```bash
git fetch origin
```
Только загрузить изменения, но **не сливать** их (позволяет посмотреть, что изменилось, без риска конфликтов).


```bash
git clone <URL>
```
Склонировать удалённый репозиторий в локальную папку (автоматически настраивает origin и переключает на ветку по умолчанию).

## 5. Теги

```bash
git tag
```
Показать список всех тегов.


```bash
git tag -a <тег> -m "сообщение"
```
Создать аннотированный тег на текущем коммите.  
- `-a` – аннотированный (хранит автора, дату, сообщение).  
- `<тег>` – например, `v1.0.0`.  
- `-m` – сообщение.


```bash
git tag -d <тег>
```
Удалить локальный тег.  
- `-d` – удалить.


```bash
git push origin --tags
```
Отправить все локальные теги в удалённый репозиторий.


```bash
git push origin <тег>
```
Отправить только указанный тег.


```bash
git push origin --delete <тег>
```
Удалить тег на удалённом репозитории.

## 6. Исправление и откаты

```bash
git commit --amend -m "новое сообщение"
```
Изменить **последний коммит** (сообщение или добавить забытые файлы, предварительно сделав `git add`). Создаёт новый коммит вместо старого.  
- `--amend` – изменить последний коммит.


```bash
git commit --amend --no-edit
```
Добавить файлы к последнему коммиту, не меняя его сообщение.  
- `--no-edit` – оставить сообщение без изменений.


```bash
git commit --amend --reset-author
```
Сбросить автора последнего коммита на текущие глобальные настройки `user.name` и `user.email`.


```bash
git reset HEAD~1
```
Удалить последний коммит, сбросить индекс (staging), но **оставить изменения в файлах**. По умолчанию `--mixed`.  
- `HEAD~1` – откат на 1 коммит назад.


```bash
git reset --soft HEAD~1
```
Удалить последний коммит, но **оставить изменения в индексе** (готовыми к новому коммиту).  
- `--soft` – не трогать ни индекс, ни файлы.


```bash
git reset --hard HEAD~1
```
Полностью удалить последний коммит и **все изменения** в рабочем каталоге (восстановить можно только через `reflog`).  
- `--hard` – сбросить всё, опасно!


```bash
git revert <хеш>
```
Создать новый коммит, который отменяет изменения указанного коммита. Безопасно для опубликованной истории.


```bash
git reflog
```
Показать историю перемещений HEAD – помогает восстановить коммиты после случайного `reset --hard`.

## 7. SSH-аутентификация

```bash
ssh-keygen -t ed25519 -C "ваш_email@example.com"
```
Сгенерировать SSH-ключ (рекомендуемый тип ED25519).


```bash
cat ~/.ssh/id_ed25519.pub
```
Показать публичный ключ – скопируйте его и добавьте в настройках GitHub (Settings → SSH and GPG keys).


```bash
git remote set-url origin git@github.com:username/repo.git
```
Сменить URL удалённого репозитория на SSH.


```bash
ssh -T git@github.com
```
Проверить подключение – должно вывести приветствие с вашим именем пользователя.

## 8. Stash (временное сохранение)

```bash
git stash push -m "описание"
```
Спрятать незакоммиченные изменения (сохранить в стеке стэшей).  
- `-m` – описание (необязательно, но полезно).


```bash
git stash list
```
Показать все сохранённые стэши.


```bash
git stash pop
```
Применить **последний** стэш и удалить его из списка.


```bash
git stash apply
```
Применить последний стэш, но **не удалять** его.


```bash
git stash drop stash@{0}
```
Удалить конкретный стэш (без применения).  
- `stash@{0}` – номер из списка.


```bash
git stash clear
```
Удалить все стэши (осторожно).

## 9. Rebase (переписывание истории, опасно!)

```bash
git rebase <базовая_ветка>
```
Перенести текущую ветку на вершину указанной ветки (делает историю линейной).


```bash
git rebase -i HEAD~3
```
Интерактивный rebase для трёх последних коммитов. В редакторе можно:
- `pick` – оставить как есть.
- `squash` (s) – объединить с предыдущим коммитом.
- `reword` (r) – изменить сообщение.
- `edit` (e) – изменить содержимое.
- `drop` – удалить коммит.

После rebase, если ветка уже была запушена:
```bash
git push --force-with-lease
```
(вместо опасного `--force`).

**Важно:** Не делать rebase для общих веток (например, `main`).

## 10. Bisect (поиск коммита с багом)

```bash
git bisect start
git bisect bad HEAD          # текущий коммит – плохой
git bisect good <хеш>        # известный хороший коммит
```
Git переключается между коммитами. После каждого переключения проверяйте программу и помечайте:


```bash
git bisect good   # если в этом коммите всё работает
git bisect bad    # если баг присутствует
```
Когда Git найдёт «плохой» коммит, он покажет его хеш.


```bash
git bisect reset
```
Завершить поиск и вернуться в исходное состояние.

## 13. Перемещение между коммитами (по хешу и тегу)

```bash
git checkout <хеш>
```
Переключиться на конкретный коммит (состояние `detached HEAD`).


```bash
git checkout <тег>
```
Переключиться на состояние, отмеченное тегом.


```bash
git checkout main
```
Вернуться в ветку `main`.


Чтобы создать новую ветку от произвольного коммита:
```bash
git checkout -b <новая_ветка> <хеш>
```

## 14. Алиасы (сокращения)

Настройте удобные сокращения, чтобы ускорить работу:
```bash
git config --global alias.lg "log --oneline --graph --all"
git config --global alias.co "checkout"
git config --global alias.br "branch"
git config --global alias.st "status"
git config --global alias.cm "commit -m"
```
Теперь можно использовать:
- `git lg` – красивый граф всех веток.
- `git co` – вместо `checkout`.
- `git st` – вместо `status`.

## 15. Pull Request (кратко)

**Это не команда Git, а процесс на GitHub.**

1. Запушьте свою фича-ветку: `git push -u origin feature/...`

2. На GitHub откройте раздел Pull Requests → New Pull Request.

3. Выберите `base: main` и `compare: ваша_ветка`.

4. Заполните описание, добавьте чек-лист, скриншоты.

5. Для незавершённой работы используйте **Draft PR**.

6. После ревью и проверок нажмите **Merge**.

7. Удалите ветку на GitHub (предлагается автоматически).

## 📌 Важно!

- Всегда используйте `git status` перед коммитом.
- Не пушите напрямую в `main`.
- Для отката опубликованных изменений используйте `git revert`, а не `reset`.
- Следуйте соглашению о коммитах (Conventional Commits).
- Регулярно делайте `git pull` перед началом работы.
