# Конфигурация системы

Этот файл описывает структуру конфигурации системы. Настройки хранятся в `Config Manager`, загружаются из `config.json` при запуске и могут изменяться через UI.

## Структура конфигурации

- `vision`
  - `cameras`
    - `cam1`
      - `detection_enabled: bool` — включена ли обработка видеопотока этой камеры.
      - `address: str` — IP-адрес камеры.
      - `port: int` — порт видеопотока.
      - `rtp_enabled: bool` — использовать ли RTP для видеопотока.
      - `buffer_size: int` — размер буфера видеопотока.
      - `detector_class: str` — класс детектора.
      - `tracker_class: str` — класс трекера.
    - `cam2`
      - те же параметры, что и у `cam1`.
    - `cam3`
      - те же параметры, что и у `cam1`.
  - `distance`
    - `source: str` — активный источник дальности.
      - допустимые значения на текущем этапе:
        - `"stereo"`
        - `"manual"`
      - в будущем могут быть добавлены другие источники, например `"lidar"`.
    - `manual_distance: float` — постоянная дальность, задаваемая пользователем при ручном режиме.
    - `stereo`
      - параметры стереозрения и синхронизации кадров.
      - конкретный набор параметров будет определён при реализации стереомодуля.
  - `camera_stale_timeout: float` — время без нового кадра, после которого видеопоток считается устаревшим.
  - `simulation_mode: bool` — использовать ли вместо реальных камер источник симуляции.

- `turret`
  - `serial`
    - `port: str` — последовательный порт STM32.
    - `baudrate: int` — скорость UART.
    - `timeout_ms: int` — таймаут ожидания ответа.
    - `retry_count: int` — число повторных попыток при ошибке связи.
  - `controller`
    - `pid_kp_x: float` — пропорциональный коэффициент PI-регулятора по оси X.
    - `pid_ki_x: float` — интегральный коэффициент PI-регулятора по оси X.
    - `pid_kp_y: float` — пропорциональный коэффициент PI-регулятора по оси Y.
    - `pid_ki_y: float` — интегральный коэффициент PI-регулятора по оси Y.
  - `backlash`
    - `x: float` — компенсация люфта по оси X.
    - `y: float` — компенсация люфта по оси Y.
  - `emulate_stm32: bool` — использовать ли эмулятор STM32 вместо реального устройства.

- `ui`
  - `default_camera: int` — камера, отображаемая при запуске.
  - `show_fps: bool` — показывать ли FPS.
  - `camera_stale_timeout` не дублируется здесь: UI использует значение из настроек Vision/видеопотока.
  - дополнительные параметры отображения могут быть добавлены по мере реализации интерфейса.

- `supervisor`
  - `enabled: bool` — включён ли Supervisor.
  - `heartbeat_timeout: float` — допустимое время без heartbeat до фиксации ошибки.
  - автоматический перезапуск потоков на первом этапе не используется.

## Что пока требует уточнения

В текущем текстовом описании есть противоречие по параметрам конкретных детекторов и трекеров:

- в разделе Vision сказано, что параметры алгоритмов не хранятся в `Config Manager`, а передаются во внутренний словарь при создании экземпляра;
- в разделе UI сказано, что размер окна, шаг, пороги и параметры трекера изменяются через расширенные настройки и передаются через `Config Manager`.

До отдельного этапа проверки архитектуры эти параметры не включены в окончательную структуру конфигурации.

## Пример общей формы

```text
vision
├── cameras
│   ├── cam1
│   ├── cam2
│   └── cam3
├── distance
│   ├── source
│   ├── manual_distance
│   └── stereo
├── camera_stale_timeout
└── simulation_mode

turret
├── serial
├── controller
├── backlash
└── emulate_stm32

ui
├── default_camera
└── show_fps

supervisor
├── enabled
└── heartbeat_timeout
```
