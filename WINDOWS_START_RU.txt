NavMin Windows — два режима
===========================
1. Распаковать обновление ПОВЕРХ папки navmin_main_1, сохранив структуру src/navmin/...
2. Не удалять config/navmin.json или config/calibration: обновление их не заменяет.
3. Открыть Start_NavMin_Windows.bat.

[1] DEMO: программная STM32 (FakeTransport) + два искусственных видеопотока
    через GStreamer appsrc -> RTP/JPEG UDP. Не нужен COM-порт и Raspberry Pi.
    Изображения связаны с положением виртуальной платформы. Включите моторы
    кнопкой внизу: RELATIVE позволяет поворачивать камеру кликом; TRACKING —
    выбирать обнаруженную белую движущуюся точку для сопровождения.
    ESC открывает окно оператора с PID и настройками tracking.
    Меню «Калибровка движения»: отмечайте один и тот же неподвижный крестик
    до и после остановки, а не движущуюся белую точку.
    Модель идеальная: масштаб 1, без люфта и инерции; остановка мгновенная.
    Стереодальность не моделируется, используется ручная дальность.
[2] REAL: штатный NavMin с реальными камерами и контроллером STM32.
[3] REAL CHECK: проверка настройки перед реальным запуском.
[4] DEMO CHECK: диагностика без оборудования.

Для реального режима:
- В config/navmin.json указать корректный COM-порт STM32 (например COM4),
  параметры камер и исправные калибровки для фактического оборудования.
- Проверить аппаратный аварийный останов и безопасное расположение установки.
- PASS для UDP и COM в статическом preflight не подтверждает наличие кадров
  и успешный обмен с STM32. Требуется проверка на самом ПК с аппаратурой.

Предварительные условия: существующая .venv с Python 3.13, PyQt6,
OpenCV, PyGObject/gi и GStreamer с appsrc, jpegparse, rtpjpegpay, udpsink,
udpsrc, rtpjpegdepay, jpegdec, videoconvert, appsink.

Обратите внимание: режим DEMO не доказывает работоспособность физической
платформы. Режим REAL не включает двигатели автоматически из BAT-файла,
но позволяет оператору управлять реальной установкой через интерфейс.

Если есть ошибка: сохраните вывод окна и соответствующий logs/navmin-.../runtime.log.

Кнопка «Сохранить и применить калибровку выбранной оси» сама сохраняет поправку:
DEMO — в config/demo-motion.json; REAL — в конфигурацию текущего запуска.
Поправка действует для следующих движений RELATIVE без перезапуска.
Пункт [1] DEMO автоматически подхватывает сохранённую калибровку.
Явный --demo-config задаёт другой файл DEMO; камеры и транспорт остаются демо.

REAL Overview: локальный config/calibration/overview.json обновлён параметрами
K, D, NEW_K из camera_view.py для 1296x976. Прежний файл сохранён рядом в .bak.
При другом разрешении требуется соответствующая калибровка.
